# 0.252.0 — Modular Binder & Artwork

V252 moves Binder rendering and card-art delivery out of the legacy artwork runtime and into maintainable ES modules.

## Architecture
- Binder owns a dedicated tiny compatibility bridge (`runtime/binder-bridge.js`).
- `runtime/artwork.js` is no longer loaded by the runtime manifest.
- Artwork cache, resolver, queue, database access, Binder renderer and inspector now live in `src/` modules.
- Existing V239 IndexedDB cache keys are preserved so previously cached artwork remains reusable.
- Rank-frame IMG hydration was extracted from the old artwork runtime into `src/systems/rank-frame-renderer.js`.

## Mobile performance
- Current Binder page has highest artwork priority.
- Previous/next pages prefetch next.
- Remaining Binder artwork fills quietly during idle time.
- iOS/in-app browsers use two concurrent artwork network tasks; Android uses four.
- Binder opens immediately without a blocking full-collection artwork overlay.

## Safety
- Artwork code never changes card ownership or quantity.
- Card-back URLs are explicitly rejected as valid fronts.
- Failed cards can be repaired individually.
- Repair diagnostics report only unresolved artwork records.
- Save schema remains unchanged at version 1.
