# V260 release limits and technical debt

This branch is a review candidate, not a claim of complete production or physical-device certification.

1. Production SQL has not been applied. Authenticated two-account Supabase staging acceptance remains required. Public Auth/API health checks confirm reachability, not RLS permission for a signed-in player or production migration compatibility.
2. Cash Stakes is intentionally unavailable. The existing project has no safe server-owned cash ledger for Stakes. Enabling escrow against client-uploaded balances would be unsafe. The server explicitly rejects stake/RP-wager requests; the authority document specifies the remaining ledger work. Ranked RP is never a player-entered wager.
3. Ordinary pack currency, sealed economy and some historical NPC/local market paths remain client-authoritative. Shared transactions and capped NPC purchasing are improvements, not complete anti-cheat. A protected server ledger and inventory provenance remain the next economy migration.
4. Chromium mobile/touch viewport tests are simulations. Samsung Internet, Chrome Android, iPhone/iPad Safari, audio/haptics, home indicator, toolbar resize, background/resume and standalone PWA behavior require physical-device testing. WebKit engine installation was blocked by the environment's download policy; no WebKit pass is claimed. No measured physical-device 60fps certification is claimed.
5. Historical quantities aggregate copies by card ID. Fully independent per-copy conditions and every reverse/holo variant cannot be reconstructed. Master Set+ implements actual graded-collection/8+/10 goals, with local population clearly labelled; no global population is invented.
6. Journals and new career counters begin with available actual events. Missing historical acquisition, pack-value, sale and grading totals are not invented. V260-era totals are labelled. Achievement IDs/earned rewards are preserved; a comprehensive historical achievement merger and full removal of compatibility code remain technical debt.
7. Daily contracts, featured sets, walk-ins, Card Show offers, auction lots, mystery binders, NPC trades and existing challenges use the game-day system. Generic legacy online-flipping/job compatibility functions still exist behind the old runtime; their code removal requires further dependency extraction. Existing sealed market pricing and offers remain in the reused sealed engine.
8. The isolated preview disables online accounts/cloud mutations, so it cannot exercise live P2P multiplayer. Card art and catalogs still need network access. A local HTTP LAN preview does not certify service-worker installation; use a separate HTTPS preview host for that test.
9. Legacy CSS/runtime is large. V260 centralizes new surfaces and routing while preserving dependent runtime IDs; it does not claim the entire historic style stack has been eliminated.

Recommended next update: protected server ledger/provenance, staging migration rehearsal and two-account acceptance, followed by physical mobile/PWA certification. Only then consider enabling cash Stakes. Keep future seasonal reset/cosmetic distribution work additive and reviewable.
